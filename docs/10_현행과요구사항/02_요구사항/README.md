# 요구사항

요구 한 건은 현업이 관찰할 결과를 설명한다. 고객 주문, 코일, 기준코드, 계획 버전 등 영향을 받는 대상을 명시하고, 여러 시스템에 걸치면 참여 시스템과 업무의 최종 확인 주체를 적는다.

| 요구사항 ID | 업무 결과와 출처 | 소유 역할·상태 | 목표 프로세스 | 기능 설계 | 수용 기준·검증 결과 |
|---|---|---|---|---|---|
| 작성 항목 | 결과를 확인할 조건, 현행 시트의 탭·단계 또는 인터뷰 근거 | 검토 담당과 결정 상태 | 업무 흐름 링크 | 설계 ID·경로 | 설계서의 수용 기준 ID, 실행 증적 링크 |

기능·연계·데이터·비기능 요구를 같은 체계에서 찾을 수 있게 한다. 숫자, 허용값, 조업 중단 시 대체 절차처럼 업무 확인이 필요한 값은 근거와 결정 상태를 표시한다. 작성 예시는 품질설계의 [주문정합성검사](../../40_시스템설계/01_냉연MES/08_품질설계/주문정합성검사/설계서.md)를 참고한다.
