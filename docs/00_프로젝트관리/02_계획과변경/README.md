# 계획과 변경

업무를 일정에 넣을 때 요구사항 ID, 대상 시스템, 기능 설계 링크, 담당 역할, 선행 과제, 목표 릴리스, 현재 상태를 한 행에 적는다. 같은 공통 계약을 사용하는 두 시스템의 구현·시험 일정을 함께 확인한다.

설계 변경에는 바뀐 규칙, 영향받는 화면·API·데이터와 소비 시스템, 기존 데이터 처리, 다시 실행할 시험, 적용 버전을 남긴다. 개발 항목이나 코드 저장소가 생기면 해당 이슈·PR·빌드 링크를 설계서 및 시험 증적과 연결한다. 구현 대상 버전이 바뀐 때는 이전 결과가 어느 버전에서 나온 것인지 보존한다.
