# 개발 표준

사람과 AI가 서로 다른 시스템에서 같은 처리 방식을 재사용할 때 참고할 기록이다. 채택된 규칙에는 적용 범위, 코드 저장소의 경로 또는 패키지, 버전, 정상·실패 예시를 붙인다.

| 주제 | 팀에서 정할 내용 |
|---|---|
| 코드 배치·검증 | 시스템별 코드 저장소와 모듈 경계, 기존 공통 라이브러리, 빌드·테스트 실행 방법, 설계 ID와 변경 이력을 연결하는 방법 |
| 데이터 표현 | 날짜·시각대, 공장 영업일, 코일 중량·두께의 단위와 소수점, 누락·빈 값·0의 구분. 항목 정의의 원본은 데이터 모델에서 참조한다. |
| 오류와 기록 | 업무 오류와 일시 장애의 구분, 오류 코드 사용 방식, 호출 상관 ID, 운영 로그에 남길 식별자와 가림 항목 |
| 트랜잭션과 동시성 | 업무 확정 시점, 중복 요청 판별 키, 재시도 가능 조건, 동시 변경 충돌 처리, 취소·정정 시 원거래 참조 |

기능을 구현할 때는 설계서에 연결된 공통 규칙 버전과 기계 판독 규격을 함께 읽는다. 적용할 규칙에 미결 사항이 있으면 해당 기능·항목과 결정 주체를 기록한다. [데이터 모델](../../50_데이터와연계/01_데이터모델/README.md) · [인터페이스](../../50_데이터와연계/03_인터페이스/README.md)
