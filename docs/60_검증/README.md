# 검증

기능 설계서에 적은 수용 기준(AC)을 어떤 버전에서 누가 확인했고 어떤 결과가 나왔는지 기록한다. 검증 범위는 냉연 MES, 표준관리시스템, 파트너 포털, 생산계획 최적화엔진과 해당 업무에 필요한 연계다.

| 찾는 자료 | 보관 위치 |
|---|---|
| 기능 내부 규칙, 송수신 양쪽이 약속한 규격의 검증 결과 | [단위·연계계약 시험](01_단위와연계계약시험/README.md) |
| 여러 시스템을 거치는 종단 간 업무, 현업의 인수 판정 | [통합시험과 사용자 인수시험](02_통합시험과사용자인수시험/README.md) |
| 응답 지연, 장애 회복, 교대·라인 환경에서의 검증 | [비기능·현장 검증](03_비기능과현장검증/README.md) |

각 실행 기록에는 대상 시스템·기능, [통합설계서](../40_시스템설계/README.md)의 AC 번호 또는 해당 절 링크, 시험 환경·빌드/설정 버전·실행 시각, 입력과 기대값, 실제값, 판정자와 근거를 남긴다. 증적은 해당 시험 곁에 한 번 보관하고 로그·화면·메시지의 실행 식별자로 연결한다. 실패 건은 결함과 수정 빌드의 재시험 결과를 연결해 처음 결과도 확인할 수 있게 한다.

아래 업무 예시는 시험 후보로 사용한다. 여러 시스템의 책임이나 처리 기준이 미결이면 근거 문서와 미결 항목을 먼저 연결하고 해당 시험의 판정은 보류한다.
