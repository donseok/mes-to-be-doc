## 시스템 설계의 업무 분류

업무별 목차에서 기능 폴더를 찾아 검토할 범위를 확인하고, 기능의 기본·상세설계는 해당 폴더에 한 파일로 작성한다. 팀원이 수정하고 같은 인수 사례로 검증할 수 있는 크기를 기능 한 건의 기준으로 삼는다.

```text
40_시스템설계/
├─ 01_냉연MES/
│  ├─ 01_기준정보       02_판매생산계획   03_납기관리       04_원부재료관리
│  ├─ 05_라인투입관리   06_조업관리       07_생산관제       08_품질설계
│  ├─ 09_품질판정       10_야드관리       11_사내운송       12_출하관제
│  └─ 13_통합관제       14_출력물관리
├─ 02_표준관리시스템/
│  ├─ 01_기준정보관리
│  ├─ 02_표준용어관리
│  └─ 03_변경승인과배포
└─ 03_위성시스템/
   ├─ 01_파트너포털/
   │  ├─ 01_협력사계정과권한     02_위탁임가공
   │  └─ 03_부재료와도료사       04_사외창고
   └─ 02_생산계획최적화엔진/
      ├─ 01_입력과제약
      ├─ 02_실행과결과
      └─ 03_재편성과계획채택
```

**표준관리시스템**의 설계서는 표준용어 등록, 기준정보 변경, 배포 확인처럼 프로그램이 수행하는 동작을 정의한다. **데이터와 연계**에는 각 시스템이 함께 쓰는 용어와 코드, 데이터의 원본과 수정 권한, 송수신 형식을 적는다. 예를 들어 규격약호를 변경하는 화면은 표준관리시스템, 적용일 기준으로 약호를 조회해 주문을 판정하는 규칙은 MES 품질설계, 약호의 키·버전·배포 계약은 공통 데이터와 연계에서 찾는다. 각 항목의 실제 소유자와 배포 경로는 업무 확인 후 정한다.

**위성시스템**은 각각 자체 화면 또는 계산 로직, 권한, 데이터, 오류 처리와 인수 기준을 갖는다. 예를 들어 엔진의 계산 불가 처리와 계획안 반환은 엔진 설계서에, 생산관리자가 계획안을 채택하고 작업지시를 갱신하는 절차는 MES 계획 설계서에 둔다. 두 시스템이 주고받는 계획 버전과 응답 형식은 공통 인터페이스 계약에서 한 번 정의한다. SAP S/4HANA, 현장 Level 1.5/2, F-MES 등 주변 시스템과의 연계는 실제 업무·송수신 범위가 확인되는 단위로 등록한다.

## 팀원과 AI가 함께 쓰는 통합설계서

한 기능의 기본설계와 상세설계를 `설계서.md`에 이어서 작성한다. 업무 담당자는 앞부분의 목적·범위·정상/예외 흐름으로 검토를 시작하고, 개발자는 같은 문서에서 결정표·필드·상태 전이·트랜잭션·오류·인수 기준까지 확인한다. 화면, API, DB, 테스트에서 같은 규칙을 사용하면 규칙 ID를 참조한다. [작성이 가능한 설계서 양식](90_작성표준/통합설계서_양식.md)

| 단계 | 담당자가 남기는 것 | 다음 사람이 찾는 방법 |
|---|---|---|
| 요구와 업무 | 요구 ID, 근거, 목표 흐름, 업무 완료 조건 | 업무 색인에서 대상 시스템과 기능으로 이동 |
| 기능 설계 | 설계 ID·개정·상태, 업무 규칙, 성공·실패 결과, 미결 질문 | 기능 폴더의 `설계서.md`에 기록된 버전과 적용 범위 확인 |
| 구현 | 설계 개정, 링크된 계약·스키마·예시 입력, 코드 변경 또는 PR | 코드 변경에 설계 ID와 인수 사례 ID를 연결 |
| 검증·인수 | 실행한 빌드·환경·입력, 기대값과 실제값, 결함과 재시험 결과 | 기능의 인수 기준에서 `60_검증` 증적을 추적 |

**작성 예시.** 영업포털이 MES에 주문 항목 정합성 검사를 요청하는 흐름을 품질설계 시트에서 가져왔다. 예시 설계서는 그 안의 작은 판정 하나를 골라 정상, 경계, 역전, 누락, 형식 오류, 오류 우선순위까지 입력·기대값으로 표현한다. 설명용 값은 `EX-`와 `draft`로 표시했다. 실제 검사항목이나 주라인·대체라인 선택에 미결정이 있으면 그 질문을 운영 설계에서 먼저 해결한다. [예시 설계서](40_시스템설계/01_냉연MES/08_품질설계/주문정합성검사/설계서.md) · [인수 예시 JSON](40_시스템설계/01_냉연MES/08_품질설계/주문정합성검사/인수예시.json)

## 기존 문서 사용 방법

MTO·MTS 분석서 7개와 22장 시뮬레이션 장표·원본·도구는 같은 묶음으로 `10_현행과요구사항/03_기존검토자료`에 배치했다. 기존 권고를 채택할 때는 D1~D24 등 출처 번호, 채택 범위, 결정 근거를 해당 기능의 요구·설계에 연결한다. 품질설계 시트와 현행 위키는 원본 링크로 연결해 현업이 편집하는 곳과 설계서의 근거가 이어지게 했다. [기존 자료 색인](10_현행과요구사항/03_기존검토자료/README.md)
