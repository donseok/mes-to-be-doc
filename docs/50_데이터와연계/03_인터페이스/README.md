# 인터페이스

연계 후보는 [인터페이스 대장](인터페이스대장.csv)에 등록한다. 네 구축 시스템 사이의 연결과 SAP S/4HANA·현장 Level 1.5/2 등 외부 시스템과의 연결을 구분한다. 대장의 초안은 검토용이며 실제 송수신 주체·방향·필드·프로토콜과 업무 소유자는 계약 검토에서 확정한다.

## 계약 보관 단위

업무와 방향이 정해지면 대장에 안정적인 계약 ID를 부여하고 이 폴더 아래에 해당 ID의 디렉터리를 만든다. 한 요청과 그 응답은 같은 계약에서 정의한다. 독립적으로 발행되는 이벤트는 별도 계약으로 등록한다.

| 항목 | 작성 방법 |
|---|---|
| 계약 식별 | 업무 이벤트 또는 호출 목적, ID, 버전, 상태, 담당자, 송신·수신 주체와 적용 환경, 관련 기능 설계·요구사항·테스트 ID |
| 데이터와 시점 | 호출 또는 발행 조건, 동기·비동기 방식, 스키마와 예시, 키·단위·유효시각·시간대, 응답 또는 확인 시점 |
| 처리 보장 | 업무 키·메시지 ID·상관 ID, 중복 판별, 처리 순서, 제한시간, 재전송·정정·취소 주체, 실패 내역과 재처리 결과 대사 |
| 오류 처리 | 오류 코드와 의미, 입력 오류·업무 거절·통신 실패를 구분하는 응답, 호출자 후속 동작과 운영자 재처리 조건 |
| 버전 변경 | 필수 필드·코드 의미·단위 변경 시 영향받는 소비자, 병행 기간과 폐기 시점, 신·구 메시지를 사용한 호환성 시험 결과 |

## 사람이 검토하고 프로그램이 읽을 파일

채택한 방식에 맞춰 HTTP API는 `openapi.yaml`, 메시지·파일은 `schema.json` 또는 해당 시스템의 원본 규격으로 표현한다. CSV·고정길이 파일은 인코딩, 구분자·필드 길이, 헤더, 레코드 종료, 재전송 단위까지 명시한다. 현장 연계는 장치·라인 키, 수집시각과 수신시각, 통신 단절 후 누락 검출 방법도 확인한다.

계약 폴더에는 업무 의미·책임·변경 이력을 적고 `examples/`에 정상, 업무 거절, 중복·재전송 예시 중 해당 사례를 둔다. 계약 승인 시 버전 또는 Git 리비전을 고정해 구현과 계약 테스트가 같은 원본을 읽게 한다. 승인 전에 만든 예시에는 가정과 미확정 항목을 표시한다.
