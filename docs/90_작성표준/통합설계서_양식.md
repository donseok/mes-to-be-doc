# <기능명> 설계서

목적, 업무 흐름, 구현 명세, 인수 기준을 이 문서 한 곳에 작성한다. 머리말 목록은 본문에서 사용한 ID로 채운다. 공통 계약은 문서 경로와 버전 또는 Git 개정을 함께 적는다. 해당 사항이 없는 항목은 이유를 짧게 남긴다.

## 1. 목적과 책임 경계

| 항목 | 작성 내용 |
|---|---|
| 업무 목표와 완료 조건 | 어떤 사용자가 무엇을 마쳐야 하는가. 업무 완료를 어떤 결과로 확인하는가. |
| 범위와 전후 업무 | 시작 조건, 끝나는 지점, 선행·후행 기능과 담당 시스템. |
| 근거·요구사항 | 요구 ID와 원본 위치, 출처 또는 회의 결정. 현행 사실·설계 결정·미결 질문을 구분한다. |
| 참여자와 권한 | 실행·조회·승인할 역할, 공장·라인·협력사별로 접근 가능한 데이터 범위. |

## 2. 업무 흐름과 상태

| 순서 | 주체·트리거 | 사전 상태·입력 | 처리·다음 상태 | 분기·실패 시 이동 |
|---|---|---|---|---|
| 1 | <사용자 조작/메시지/배치> | <시작 조건> | <성공 결과> | <예외 단계/규칙 ID> |

수정·취소·재처리가 있는 경우 허용 상태, 되돌릴 상태, 후속 작업의 처리까지 적는다.

## 3. 결정 규칙과 계산

| 규칙 ID | 우선순위·적용 조건 | 계산식·판정·동작 | 결과·예외 코드 | 요구 ID |
|---|---|---|---|---|
| <규칙 ID> | <여러 조건 동시 충족 시 순서> | <키·단위·정밀도·경계값 포함 여부> | <기대 결과> | <요구 ID> |

시간·공장 달력·기준정보를 참조하면 적용 기준일과 버전을 명시한다. 정상, 경계, 누락·중복 입력을 각각 판정할 수 있도록 적는다.

## 4. 사용자·호출자 접점과 데이터

| 접점·데이터 | 구체화할 내용 |
|---|---|
| 화면·작업 단위 | 진입 경로, 입력 가능 조건, 조회·저장·취소 동작, 사용자에게 표시할 결과와 오류. 파일·배치·API 기능은 해당 호출자 관점으로 적는다. |
| 입력·출력 | 업무명과 프로그램 필드명, 형식, 필수·널·기본값, 단위·길이, 코드 집합, 유효 범위, 예시와 공식 계약 참조. |
| 데이터 읽기·쓰기 | 원천 시스템, 엔터티·키, 조회 시점, 생성·수정·이력, 트랜잭션 경계 및 커밋 후 이벤트. 공통 데이터 정의로 연결한다. |
| 시스템 간 호출 | 계약 ID·개정·경로, 생산자·소비자, 호출 시점·방향, 동기/비동기, 실패 응답. 별도 연계가 없으면 실행 경계를 적는다. |

## 5. 예외·운영 조건

| 상황 | 검출 조건 | 호출자·사용자 결과 | 복구·운영 |
|---|---|---|---|
| <업무 오류 또는 기술 장애> | <규칙/실패 시점> | <결과 코드·메시지·저장 상태> | <재시도 주체, 중복 방지 키, 대사/취소, 기록·알림> |

기능 특성에 따라 동시 처리, 권한 위반, 개인정보·감사 로그, 설비 또는 시스템 정지 시 동작, 성능 목표와 측정 조건을 적는다. 공통 기준은 출처를 연결하고 기능별 차이만 적는다.

## 6. 인수 사례와 추적

| 인수 ID | 연결한 요구·규칙·계약 | 주어진 상태·입력(Given) | 수행(When) | 검증 가능한 기대값(Then) |
|---|---|---|---|---|
| <인수 ID> | <요구·규칙·계약 ID> | <정상·경계·실패별 입력> | <동작> | <출력값·상태·저장 건수/후속 이벤트> |

자동화용 예시 파일을 두면 입력과 기대 출력의 필드명을 계약과 맞추고 같은 인수 ID를 쓴다. 실제 실행 결과와 결함은 검증 폴더에 설계 ID·개정으로 연결한다.
