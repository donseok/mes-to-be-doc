# 주문정합성검사 설계서 작성 예시

**이 문서는 초안 예시다.** 아래 1절은 품질설계 시트에서 확인한 흐름이다. 2~5절의 두께 항목·정밀도·판정 코드와 테스트 값은 팀원이 결정표를 검토하고 AI가 같은 사례로 테스트를 작성하는 방법을 보여주기 위해 만든 예시다. 운영 구현의 기준으로 쓸 필드와 규칙은 6절의 질문으로 남아 있다.

## 1. 확인된 업무 흐름과 담당 경계

| 시트 순서 | 주체 | 기록된 동작 |
|---|---|---|
| 1 | ERP 영업포털 | 주문 항목을 자체 점검한다. |
| 2~3 | 영업포털 → MES 품질설계 → 영업포털 | 영업포털이 주문 항목 간 정합성 검사를 호출하고 MES가 결과를 응답한다. |
| 4 이후 | MES 품질설계 | 주문의 생산가능라인을 확인하고 허용단중·규격약호 등을 점검한다. 주라인과 대체라인 중 어느 기준을 후속 단계에 전달할지는 시트에 질문으로 남아 있다. |

이 설계 예시의 경계는 순서 2~3 내부의 **입력 한 쌍을 판정하는 함수**다. 실제로 비교할 필드는 EX-Q-01에서 영업·품질과 확인한다. API 인증·접근 범위·주소·전송 형식·응답 코드는 개발 착수 전에 계약 담당자와 구체화할 항목이다. ## 2. 설명용 요구와 판정기 접점

**EX-REQ-01**. 정합성 검사 호출자가 주문 두께의 하한과 상한을 입력했을 때 두 값의 순서를 검사할 수 있어야 한다. 함수가 예시 입력 JSON 값을 받아 예시 결과 객체를 반환한다. 로그인, 외부 조회, 저장, 후속 라인 선택은 이 함수의 책임 범위 밖이다.

| 방향 | 필드 | 정의 |
|---|---|---|
| 입력 | `minThicknessUm`, `maxThicknessUm` | 두 필드는 각각 필수다. 단위는 µm, 허용 값은 1 이상 10,000 이하의 수학적 정수다. 1.0은 1과 같은 값으로 처리한다. 문자열·불리언·null은 형식 오류다. 두 필드 외 추가 필드는 무시한다. |
| 출력 | `result` | `PASS`, `FAIL`, `INVALID_INPUT` 중 하나. |
| 출력 | `code` | 아래 결정표의 코드 하나. 출력 필드는 `result`와 `code` 두 개다. |

## 3. 결정표와 상태 변화

위에서 처음 일치하는 행으로 종료한다. 호출 전후에 저장되는 데이터와 전달되는 후속 이벤트는 없다. 동일 입력의 결과는 호출 횟수에 관계없이 동일하다.

| 순서 | 규칙 ID | 조건 | result | code |
|---|---|---|---|---|
| 1 | EX-RULE-01 | 입력이 객체가 아니거나 필수 필드 중 하나라도 누락·형식 오류·범위 초과 | INVALID_INPUT | FIELD_INVALID |
| 2 | EX-RULE-02 | 두 값이 모두 유효하고 하한 > 상한 | FAIL | RANGE_REVERSED |
| 3 | EX-RULE-03 | 두 값이 모두 유효하고 하한 ≤ 상한 | PASS | RANGE_OK |

호출자는 형식 오류면 입력을 수정하고, 범위가 역전되면 두 값의 업무 의미를 확인한 뒤 다시 검사할 수 있다. 예시 범위에는 사용자 화면, 운영 로그 수집, 응답시간 목표가 없다.

## 4. 인수 사례

모든 행에서 실행 동작은 ‘판정기를 한 번 호출’이다. 표와 JSON은 같은 인수 ID를 사용한다. JSON에는 비교할 기대 객체 전체를 담았다. [입력·기대값 원본](인수예시.json)

| 인수 ID | 연결 규칙 | 주어진 입력(하한, 상한) | 기대 result / code |
|---|---|---|---|
| EX-AC-01 | EX-RULE-03 | 800, 1200 | PASS / RANGE_OK |
| EX-AC-02 | EX-RULE-03 | 10000, 10000 | PASS / RANGE_OK |
| EX-AC-03 | EX-RULE-02 | 1200, 800 | FAIL / RANGE_REVERSED |
| EX-AC-04 | EX-RULE-01 | 상한 누락 | INVALID_INPUT / FIELD_INVALID |
| EX-AC-05 | EX-RULE-01 | 하한이 문자열 | INVALID_INPUT / FIELD_INVALID |
| EX-AC-06 | EX-RULE-01 | 10001, 800 (범위 초과와 역전이 함께 발생) | INVALID_INPUT / FIELD_INVALID |

## 5. 구현 인계 단위

설계 ID `EX-DSN-MES-QUAL-001`, 개정 `0.1`의 구현 연습에서는 3절 결정표대로 판정기를 작성하고, JSON의 `cases[].input`을 넘겨 응답을 `cases[].expected`와 비교한다. 운영 기능으로 채택하는 시점에는 실제 주문 필드·권한·계약 오류를 합의하고 운영용 요구·설계·인수 ID를 부여한다. 이 예시의 `contracts`는 빈 목록이다.
